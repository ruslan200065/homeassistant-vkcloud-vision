# Аудит и план развития

Начальная точка форка — `b86f221`. Проверены действия Home Assistant, конфигурация и миграции, OAuth, обработка ответов VK Cloud, сохранение кадров, обучение и удаление лиц, документация и GitHub Actions.

| Приоритет | Найденная проблема | Что изменилось в 1.7 |
|---|---|---|
| P0 | Платформа загружалась независимо от записи конфигурации, а действия могли обращаться к пустому списку записей | Сущность привязана к записи и выгружается вместе с ней |
| P0 | Снимок можно было записать за пределами разрешённых каталогов, а несколько камер записывали в один файл | Проверка пути, атомарная запись и подстановка `{camera}` |
| P1 | Ошибка одного режима скрывала успешный результат другого, а пауза выполнялась даже после последней попытки | Частичные результаты сохранены, задержки ограничены, изменяющие базу лиц запросы выполняются один раз |
| P1 | Параллельные действия могли одновременно обновить OAuth-токен; новый refresh token терялся при перезапуске | Обмен сериализован, новый refresh token записывается в конфигурацию |
| P1 | Разметка следующего кадра могла попасть на первый кадр | Выбор кадра через `snapshot_index` и сопоставление по имени изображения |
| P2 | Локальные псевдонимы сохранялись после удаления лиц в облаке | Удаление псевдонимов по области и идентификатору |
| P2 | CI проверял упаковку, но не поведение действий | Добавлены регрессионные тесты и запуск в CI |

После первого этапа добавлены фильтр классов в действии `detect_objects` и диагностический отчёт Home Assistant по камерам и действиям.

## Следующие этапы

1. **Дымовой тест с VK Cloud.** Проверить на тестовом проекте все три действия, ответы при превышении квоты и форматы метаданных для разных режимов. Зафиксировать обезличенные примеры ответов в тестах.
2. **Управление расходами.** Добавить настраиваемый интервал между запросами к одной камере и ограничение параллелизма на запись интеграции. Сначала измерить поведение автоматизаций на очереди и определить удобные значения по умолчанию.
3. **Зоны кадра.** Дополнить фильтр классов фильтром по области, чтобы автоматизация реагировала, например, на человека у входа. Покрыть граничные координаты и камеры с разным разрешением.
4. **Диагностика облачных запросов.** Дополнить счётчики действий обезличенными метриками задержек, ограничений квоты и числа повторов.
5. **Локальные файлы как источник.** После проверки ограничений API добавить отдельное действие для обработки файла из разрешённого каталога, с тестами доступа и размера входных данных.
